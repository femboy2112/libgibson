# v0.9.0 design: terminal capability probe

Status: design plus a RED test slice. The stubs are in `src/capability/probe.rs`, the failing
tests in `tests/capability_probe.rs`. Nothing is wired into the live terminal path yet.

Goal: turn `Capability::Unknown` into `Supported` or `Unsupported` for sixel and kitty
graphics, and pick a block-glyph tier (octants, sextants, basic), without guessing from
`TERM` and without a query that can change terminal state (issue #139: tri-state plus
USER_FORCED, no destructive probing).

The contract this exists to keep, the truthful fallback: **LibGibson never claims pixels it
cannot show.** `Supported` needs positive evidence. Silence is `Unknown`, never `Supported`,
and a timeout is never `Unsupported`.

Facts marked **[unsure]** were written from memory of the xterm and kitty documents and were
not re-read or measured in this slice. They are collected in the last section.

## 1. Wire sequence and order

One request, written once, in this order:

| # | bytes                                            | asks                           |
|---|--------------------------------------------------|--------------------------------|
| 1 | `ESC _ G i=31,s=1,v=1,a=q,t=d,f=24;AAAA ESC \`   | kitty graphics query           |
| 2 | `CSI ? 2 ; 1 ; 0 S`                              | XTSMGRAPHICS: sixel geometry   |
| 3 | `CSI ? 1 ; 1 ; 0 S`                              | XTSMGRAPHICS: colour registers |
| 4 | `CSI c`                                          | DA1: the sentinel              |

DA1 is last because every terminal answers it, and answers queries in the order received.
When DA1 arrives, anything that was going to answer 1 to 3 already has. A reply to 1 to 3 that
has not arrived by then is not coming.

Properties of the request (tested on the bytes):

- It ends with `ESC [ c`, DA1 appears exactly once, and the kitty query precedes it.
- Every CSI in it is a query: final byte `S` or `c`. No `h`, `l`, `u`, `H`, `J`. No mode is
  set, no stack is pushed, nothing needs undoing.
- Query 1 is a 1x1 RGB image with `a=q`: kitty validates it and answers, and does not display
  or store it. **[unsure]** that `a=q` never stores; the kitty graphics spec says a query
  action does not display and the terminal "should" not retain it.
- Item 2 reads with `Pa=1` (read the current value). `Pv` is ignored on a read and sent as 0.

A terminal that does not know APC drops an `ESC _ ... ESC \` string silently (xterm, VTE).
The Linux console (`TERM=linux`) and `dumb` are not probed at all, see section 7. **[unsure]**
what every old terminal does with an APC string; the gate is the answer, not a guarantee.

## 2. Reply grammars

All three are parsed from a complete byte string by a pure function that returns `None` on
anything else. They do no I/O.

```
DA1       ESC [ ? Ps ( ; Ps )* ;? c           Ps = decimal, <= 65535
kitty     ESC _ G keys ; message ESC \         keys = k=v(,k=v)*, message = OK | CODE:text
XTSM      ESC [ ? Pi ; Ps ( ; Pv )+ S          Pi = item, Ps = status, Pv = values
```

- DA1: a trailing empty parameter is ignored (kitty answers `CSI ? 62 ; c`, **[unsure]**). An
  empty parameter in the middle, a non-digit, a number above `u16::MAX`, no attributes, a `>`
  prefix (secondary DA), or a missing final byte is `None`. Returns the attribute list, first
  element being the conformance level (VTE 0.76: `[61, 1, 21, 22]`). Attribute 4 means sixel.
- kitty: `i=` is read into `id`. `ok` is true only for the message `OK`. Any other message
  (`ENOENT:...`, `ENOTSUPPORTED:...`) parses and has `ok == false`. The string terminator is
  required: an unterminated string is `None`, because a half-read APC must not be taken as an
  answer.
- XTSM, per xterm ctlseqs **[unsure]**: `Pi` 1 = colour registers (`Pv` is a count), 2 = sixel
  graphics geometry (`Pv` is width then height in pixels), 3 = ReGIS geometry. `Pa` in the
  request: 1 read, 2 reset to default, 3 set, 4 read the maximum. `Ps` in the reply: 0 success,
  1 error in `Pi`, 2 error in `Pa`, 3 failure. Any other `Ps` is carried as `Other(n)` and is
  never success. Note the xterm text calls 1 "error in item", not the "bad item" of the task
  brief; both mean `Pi` was refused. VTE 0.76 answers `CSI ? 2 ; 1 ; 0 S`.

## 3. The decision table

Inputs: `ProbeEvidence` (replies that arrived before DA1 or the deadline, `da1: None` when the
sentinel never came) and an injected environment getter. Output: per capability a tri-state
and one reason. Precedence, first match wins: USER_FORCED, multiplexer, ssh, evidence.

### Kitty graphics

| evidence                                         | state       | reason             |
|--------------------------------------------------|-------------|--------------------|
| forced by the application                        | forced      | `UserForced`       |
| TMUX or STY set, non-empty                       | Unsupported | `Multiplexer`      |
| SSH_CONNECTION or SSH_TTY set, non-empty         | Unsupported | `Remote`           |
| reply with `OK`                                  | Supported   | `Replied`          |
| reply with an error message                      | Unsupported | `ErrorReply`       |
| no reply, DA1 arrived                            | Unsupported | `NoReplyBeforeDa1` |
| no reply, no DA1 (deadline)                      | Unknown     | `TimedOut`         |

A positive reply counts even if DA1 never arrived: a reply is evidence, silence is not.

### Sixel

Sixel is `Supported` only when DA1 has attribute 4 **and** XTSMGRAPHICS item 2 succeeded with
a positive width and height. DA1 4 alone is weak (some terminals advertise it without being
able to draw, and VTE's sixel getter is a stub).

| DA1                | XTSM geometry (item 2)         | state       | reason         |
|--------------------|--------------------------------|-------------|----------------|
| forced             | forced                         | forced      | `UserForced`   |
| multiplexer / ssh  | any                            | Unsupported | `Multiplexer`, `Remote` |
| none (deadline)    | any                            | Unknown     | `TimedOut`     |
| has 4              | success, width > 0, height > 0 | Supported   | `Replied`      |
| has 4              | success, zero geometry         | Unknown     | `Conflict`     |
| has 4              | error status (Ps != 0)         | Unsupported | `XtsmError`    |
| has 4              | no reply                       | Unknown     | `Da1Only`      |
| no 4               | success                        | Unknown     | `Conflict`     |
| no 4               | error status                   | Unsupported | `XtsmError`    |
| no 4               | no reply                       | Unsupported | `NoReplyBeforeDa1` |

The colour-register reply (item 1) is collected and kept in the evidence. It does not change
the tri-state in v0.9.0: a terminal that draws sixel with 2 registers is still drawing sixel.
It is there for the renderer to size a palette later.

### Glyph tier (octants, sextants)

This is a ladder, not a tri-state, and it is decided from passive signals only. A graphics
reply says nothing about which block glyphs a terminal draws itself, and the probe has no query
for it. `Basic` is half blocks, Braille and what every font has.

| signal                                              | tier      | reason       |
|-----------------------------------------------------|-----------|--------------|
| TMUX or STY set                                     | Basic     | `Multiplexer`|
| `KITTY_WINDOW_ID` set, or `TERM=xterm-kitty`        | Octant    | `PassiveEnv` |
| `VTE_VERSION` >= 7700                               | Octant    | `PassiveEnv` |
| `VTE_VERSION` >= 7600 and < 7700                    | Sextant   | `PassiveEnv` |
| anything else (older VTE, xterm, linux, unknown)    | Basic     | `NoEvidence` |

VTE 0.76 draws sextants itself but not octants; octants arrive with 0.77 (measured on
mate-terminal 0.76; the 7700 threshold is from the VTE changelog, **[unsure]**). kitty draws
the legacy-computing block glyphs itself **[unsure]** which of them, and from which release.

The tier is passive and so is unaffected by a probe timeout: a timeout leaves a VTE 0.76
terminal at `Sextant` with pixels `Unknown`.

Not used in v0.9.0: `TERM_PROGRAM`. It names WezTerm, ghostty, iTerm and Apple Terminal, but
this slice has no measurement of what any of them draws, so none raises the tier. A terminal
joins the table when somebody measures it.

Cell pixel size (`TIOCGWINSZ` `ws_xpixel`/`ws_ypixel`, or `CSI 16 t`) is not a capability.
It is needed to size an image once `Supported`, and it is zero on some terminals that do draw
pixels, so it never makes a verdict. Out of scope for this slice.

### The two required worked examples

| terminal                | sixel       | kitty graphics | glyph tier |
|-------------------------|-------------|----------------|------------|
| VTE 0.76 (mate-terminal)| Unsupported | Unsupported    | Sextant    |
| kitty                   | Unsupported | Supported      | Octant     |

VTE 0.76: DA1 `61;1;21;22` has no 4, XTSMGRAPHICS answers status 1, there is no kitty reply,
`VTE_VERSION=7600`. kitty: the `OK` reply, DA1 without 4 and no XTSM reply, `KITTY_WINDOW_ID`.
The kitty sixel cell is `Unsupported` by the "no 4, no reply" row; kitty has no sixel.

## 4. Timeout and late replies on the owned input path

The probe reads on the same path as keys, so it must not eat keys and must not let a reply
become keys. The owned source (`tty_source`) already decodes DA1 and kitty flags replies; this
adds the probe's three reply kinds to the same decoder.

- **Deadline.** The caller passes a timeout (default 250 ms, **[unsure]** of a good default;
  ssh is excluded so the long-latency case never runs). On expiry the evidence is whatever
  arrived, with `da1: None`, and `decide` returns `Unknown`/`TimedOut` for anything not
  positively answered.
- **Draining.** An expired request is not forgotten. It stays outstanding in a `draining`
  state until its DA1 arrives or the session restores the terminal. A late kitty reply, XTSM
  reply or DA1 is consumed and dropped, never delivered as `Event::Key`. This is the failure
  the design exists to prevent: today `ESC _ G ...` would decode as Alt+`_` followed by
  letters.
- **APC and XTSM in the parser.** `parse.rs` gets an APC reader (`ESC _ ... ESC \`) and an
  `ESC [ ? ... S` reader, each producing an internal event. An APC with no terminator within a
  bound (4 KiB) is not consumed, to keep a stray `ESC _` typed by a person from swallowing
  input. **[unsure]** how the existing incremental decoder treats an `ESC _` split across reads;
  the GREEN slice must test the split.
- **Late reply, evidence side.** Replies after the deadline never change the verdict already
  handed out. A later `probe` call re-queries.
- **Stray DA1.** As with key release (#275), a DA1 answering somebody else's earlier query
  reads as "no reply before DA1" and would wrongly give `Unsupported`. So a probe is only
  written when no other query is outstanding; if one is, the probe waits. This is a
  precondition, not a repair.

## 5. Reuse of KeyboardQueries

`KeyboardQueries` in `tty_source.rs` is already a counter of outstanding requests, each
closed by a DA1 sentinel, with the "somebody else's DA1" rule and a window generation.
v0.9.0 renames and generalises it to `TerminalQueries`:

- `outstanding` becomes a FIFO of requests, each tagged `Keyboard` or `Capability`, with a
  per-request record of which replies it has seen and a `draining` flag.
- DA1 pops the oldest request. A `Keyboard` request keeps its current meaning exactly: flags
  reply seen means `Active`/`Unsupported` from the flags; DA1 first means `Unsupported`.
  `expect_keyboard_reply` / `retract_keyboard_reply` stay as thin wrappers.
- A `Capability` request collects kitty, XTSM geometry and XTSM colour replies until its DA1,
  then completes with a `ProbeEvidence`.
- Requests never interleave: a second request is not written while one is outstanding
  (section 4). That removes the case where an APC reply could belong to two requests.
- The screen-switch window (#312) applies to `Keyboard` requests only. A probe reply carries
  no key bytes, so it needs no switch window.
- Existing DA1 behaviour stays as it is until the GREEN slice, and its tests must pass
  unchanged. This slice touches none of it.

## 6. Multiplexer and ssh policy

LibGibson has no `TMUX`, `STY` or `SSH_*` detection today. Under tmux or screen, the DA1,
XTSM and kitty answers come from the multiplexer, not the outer terminal, and graphics
sequences are either swallowed or need passthrough wrapping this crate does not do. Under ssh
the pixel path is slow and the environment on the remote side describes the remote shell.

- `TMUX` or `STY` set and non-empty: kitty graphics and sixel are `Unsupported`, reason
  `Multiplexer`. The glyph tier is `Basic`, because a multiplexer can be attached from a
  different terminal than the one that started it, so `VTE_VERSION` may be stale.
- `SSH_CONNECTION` or `SSH_TTY` set and non-empty: kitty graphics and sixel are `Unsupported`,
  reason `Remote`, unless forced. The glyph tier still uses the passive signals; ssh does not
  forward `VTE_VERSION` or `KITTY_WINDOW_ID` by default, so it usually reads `Basic`, and
  `TERM=xterm-kitty`, which is forwarded, is still honest.
- The probe is not written at all in these cases (`decide` with no evidence gives the same
  verdict), so the multiplexer is never sent a sequence it might mishandle.
- An empty variable counts as unset.
- tmux 3.4 can pass sixel through when built for it, and a passthrough-aware mode could later
  turn kitty graphics on under tmux. Out of scope; it needs the opt-in below.

## 7. USER_FORCED

The application can force either pixel capability: `UserForced { kitty_graphics:
Option<bool>, sixel: Option<bool> }`, carried in the evidence. `Some(true)` gives
`Supported`, `Some(false)` gives `Unsupported`, reason `UserForced`, and it beats everything
else: positive evidence, the multiplexer policy and the ssh policy. It is how a user on tmux
with passthrough, or on ssh to a kitty they know about, turns pixels back on. `None` leaves
the probe in charge. Forcing one capability never changes the other. A forced value needs no
probe; the probe is skipped when both are forced.

`docs/KITTY_IMAGES_DESIGN.md` says LibGibson never enables pixel images from environment
hints, and sends no probe by default. This design keeps both: `from_env` stays passive and
leaves pixel fields `Unknown` (guard tests), and the probe is a separate explicit call.

The probe also does not run when `TERM` is `dumb`, `linux` or empty.

## 8. Passive signals, summary

| signal             | used for                                          | never used for         |
|--------------------|---------------------------------------------------|------------------------|
| `VTE_VERSION`      | glyph tier (7600 sextant, 7700 octant)            | pixel verdicts         |
| `TERM`             | `xterm-kitty` glyph tier; `dumb`/`linux` gate     | pixel verdicts         |
| `KITTY_WINDOW_ID`  | glyph tier                                        | pixel verdicts         |
| `TERM_PROGRAM`     | nothing yet, see section 3                        | pixel verdicts         |
| `TMUX`, `STY`      | multiplexer policy                                | -                      |
| `SSH_CONNECTION`, `SSH_TTY` | remote policy                            | -                      |
| `TIOCGWINSZ` pixels| sizing an image after `Supported`                 | any verdict            |

## 9. API (module `gibson::capability::probe`)

```rust
pub fn parse_da1_attributes(&[u8]) -> Option<Vec<u16>>;
pub fn parse_xtsmgraphics(&[u8]) -> Option<XtsmReply>;
pub fn parse_kitty_graphics_reply(&[u8]) -> Option<KittyReply>;
pub fn probe_request_bytes() -> &'static [u8];
pub fn decide(&ProbeEvidence, impl Fn(&str) -> Option<String>) -> ProbeVerdict;
impl TerminalCapabilities { pub fn with_probe(self, &ProbeVerdict) -> Self; }
```

Types: `KittyReply`, `XtsmReply`, `XtsmStatus`, `ProbeEvidence`, `UserForced`,
`CapabilityVerdict { state, reason }`, `ProbeVerdict`, `ProbeReason`, `GlyphTier`
(`Basic < Sextant < Octant`). Every new public enum and struct is `#[non_exhaustive]`, so
integration code builds values through `Default` and the parsers, and assigns fields.

Decisions:

- Parsers and `decide` are pure and take bytes and a getter, so the whole table is testable
  with no terminal and no environment.
- `with_probe` replaces a field only for `Supported` or `Unsupported`. `Unknown` keeps what was
  there, so a timed-out probe never erases a value the application set.
- `TerminalCapabilities` is `Copy` with public fields and no `#[non_exhaustive]`. Adding a
  `glyph_tier` field to it is a breaking change for anyone constructing it by literal, so v0.9.0
  keeps the tier on `ProbeVerdict` only. Whether to add the field is an open question for the
  release.
- The live entry point (a `TerminalSession`/`Context` method that writes
  `probe_request_bytes()`, collects replies through `TerminalQueries`, and returns a
  `ProbeVerdict`) is designed in sections 4 and 5 and is not in this slice.

## 10. Test plan

RED slice (this branch), all on byte strings, no terminal, no process environment:

- parsers: VTE 0.76 DA1 gives `[61,1,21,22]`; xterm-style DA1 with 4; kitty DA1 trailing
  semicolon; malformed DA1, kitty and XTSM inputs are `None` (each paired with a positive case
  so a `None` stub cannot pass); kitty `OK` and error replies; XTSM geometry, colour
  registers, status 1.
- request: ends with DA1, DA1 once, kitty query before it, XTSM reads before it, only query
  finals.
- decision: VTE 0.76 (sixel and kitty Unsupported, Sextant); VTE 0.77 Octant; old VTE Basic;
  kitty (Supported, Octant, sixel Unsupported); kitty reply on an unnamed terminal (Supported,
  Basic); kitty error reply; DA1 4 alone; DA1 4 plus geometry; XTSM success without 4; zero
  geometry; XTSM error; timeout is Unknown with reason `TimedOut`; timeout keeps the passive
  tier; a positive reply survives a missing DA1; tmux, screen, empty `TMUX`, ssh (both
  variables), USER_FORCED beating ssh and tmux, forced off beating evidence, forced with no
  evidence.
- `with_probe` applies known values and keeps unknown ones.
- guards (pass today): `from_env` and the constructors leave pixel capabilities `Unknown`.
  There is no guard for the existing DA1 parse, which has no public path.

GREEN slice adds, in-crate (`tty_source` tests, still on bytes):

- the APC and XTSM readers, including a reply split across two reads;
- `TerminalQueries`: keyboard behaviour unchanged (every existing test), a capability request
  completing on DA1, no interleaving, a stray DA1, retraction on a failed write;
- late replies after the deadline are consumed and never produce a key event;
- a typed `Alt+_` with no terminator is still a key.

Qualification before release: measure on kitty, VTE (the 0.76 box), and one sixel terminal
(foot or xterm with sixel); record DA1, XTSM and kitty replies as fixtures. Until then the
sixel and octant rows for those terminals are design, not measurement.
