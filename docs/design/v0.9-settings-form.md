# v0.9.0 design note: Settings form primitives

Status: IMPLEMENTED (experimental, opt-in, Rust-only, #433). No C ABI or header change.
Tests: `tests/ui_settings_form.rs`.

## API

```rust
pub fn toggle<A>(label: impl Into<String>, on: bool) -> Element<A>;
pub fn form_row<A>(label: impl Into<String>, control: Element<A>) -> Element<A>;
impl<A> Element<A> {
    pub fn error(self, message: Option<String>) -> Self;
    pub fn hint(self, hint: Option<String>) -> Self;
}
```

All four are exported with the rest of `src/ui/element.rs` (`gibson::ui::*` and the prelude).

### Why `error(Option<String>)` and `hint(Option<String>)`

`Option<impl Into<String>>` makes a bare `.error(None)` ambiguous (the compiler cannot pick the
`impl` type), and callers computing validation results hold an `Option<String>` already:
`.error(validate(&state))`. The cost is that a literal needs `Some("msg".to_string())`.
Alternative kept open: add `.error_text(impl Into<String>)` sugar, or accept
`impl Into<Option<String>>` if inference of `None` proves fine on the CI toolchain.

## Rendering spec

- `toggle(label, on)`: a single row, `[x] label` when on, `[ ] label` when off. Skin-styled like
  `choice` (focus, disabled, selected states stay distinguishable in mono and ANSI16). The marker
  is text, never colour alone. State is application-owned; activation never mutates it.
- `form_row(label, control)`: a row with the label on the left and the control on the right. The
  label column width is aligned across sibling `form_row`s in the same column, so controls start
  at one x position. Label and control share one terminal row at 80 columns.
  The control keeps its own key, handlers, focus and editing behaviour.
  Below 80 columns (`UiEnvironment.width < 80`) the label stacks on its own row above the
  control, and the control (with its hint and error) is indented two columns.
- `.error(Some(msg))`: one extra row directly under the control, painted with the `Tone::Danger`
  style, indented to the control column when inside a `form_row`. The message is a single row and
  is clipped on the right, never wrapped. `.error(None)` renders nothing and takes no rows, so it
  is byte-identical to omitting the call.
- `.hint(Some(text))` on a `form_row`: a dim (`styles.faint`) single-row cell after the control on
  the same row, two spaces after it. It is clipped on the right, never wrapped, never a focus
  stop, and adds no rows. `.hint(None)` is byte-identical (glyph and style, every cell) to
  omitting it. Other elements ignore `.hint`.

## Keyboard

- `toggle`: focusable (Tab order as `choice`); Space and Enter produce `on_press`. A disabled
  toggle follows a disabled `choice`: dim skin, not a focus stop, no actions.
- `form_row`: not a focus stop itself; focus belongs to the control, so there is one Tab stop
  per row. A non-interactive control (a `label`) is skipped. Label is not clickable.
- `.hint(..)`: never a focus stop.
- `.error(..)`: the error row is never a focus stop; never changes focusability; the control stays focusable with or without a message.
- `text_input` inside `form_row`: editing, paste and submit are unchanged (guard test).

## 80x24 budget

A Settings column is 8 form rows plus 1 error line: 9 rows. With the screen's own padding and a
heading that is well inside 24 rows, so nothing may clip at 80x24. Each form row is exactly 1 row
(2 with an error). Label column is the longest label in the group, capped so the control keeps at
least half the width.

## Decisions

1. Label alignment is computed per container: when lowering a vertical container, the longest
   sibling `form_row` label plus a two-column gap sets the label column, capped at half the
   environment width. No `.label_width(n)`.
2. `.error` on a bare control (outside `form_row`) paints the row at the control's own left
   edge, directly under it. Outer sizing then applies to the control inside that wrapper.
3. Narrow terminals: below 80 columns the label stacks above the control (control indented two
   columns), so labels are never clipped by a shared label column. Under 40 columns is not
   treated specially.
4. `toggle` has its own `ElementKind` with text markers `[x]` / `[ ]` and no extra selected
   glyph; selection styling rides on the base style. No skin glyph override.
5. `error` does not announce through `ChangeKind`.

## Still open

- NAV-1 interplay: Tab/arrow order across rows and any section jump keys. To be reconciled with
  the NAV-1 note.
- `choice` itself has no built-in Left/Right cycling; Enter/Space fire its `on_press`, which the
  application uses to cycle. `form_row` does not change that.
- `.hint` is stored on any element but only `form_row` renders it.
