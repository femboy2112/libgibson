## Gibson World compatibility notes

A read-only check (2026-11-20) asked whether the v0.9 drafts would block or conflict with the
Gibson World 2.0 plan (draft #439): GW1's pre-cell pixel/semantic seam and GW3's typed input. None
blocks. Two items were changed before freeze:

- **#438:** the pixel image element keeps an `Arc<RgbaRaster>` (source resolution and alpha kept)
  and carries no route; the kitty-vs-cell decision is a terminal-adapter step on the lowered frame.
- **#434:** `scoped_keys` joins prefix and key with `.`, so a user key `a.b` can alias scope `a` +
  key `b`. Treated as a bug: a RED collision test now, and GREEN rejects the reserved separator or
  uses an unambiguous encoding.

The rest is recorded here so it is not lost. None of it needs code now.

- **`ViewTransition::accepts_pointer` is a terminal-projection policy.** The freeze exists because
  cell hit-testing uses the pre-effect extent. A native backend would hit-test the transformed
  geometry, so do not put this freeze in a host action path.
- **Native backends consume `ViewTransition`, not `SurfaceFx`.** A native backend should read
  `progress` and `kind` from it. `effects() -> Vec<SurfaceFx>` is cell-integer and applies to the
  encoded `Surface`, so it is not the native animation primitive.
- **The shared seam is the resolved plane list.** When the CellEncoder Stage path is built, expose
  the resolved planes (`Arc<RgbaRaster>`, offset, clip, z) as the public intermediate that both
  the terminal fine-composite and a native adapter consume. Do not use the fixed 2x12-per-cell
  intermediate. This matches #419 stream C.
- **Pointer input gets a new `Event` variant.** `Event` is `#[non_exhaustive]`, but `MouseEvent`
  is exhaustive and cell-only (`u16` column/row). Typed or pixel pointer input should arrive as a
  new variant rather than as new fields on `MouseEvent`.
- **Native capabilities live in a separate `TargetCapabilities`.** `TerminalCapabilities` is
  `Copy` with public fields, and `capability::Capability` is not `#[non_exhaustive]`, so do not
  grow them for native backends. `GlyphTier` and the probe's pixel verdicts stay terminal-scoped.
- **GW types are not API yet.** GW's `ResolvedWorld` and `DisplayList` are illustrative, not
  accepted API, so the check could only confirm that current public APIs leave room for them.
