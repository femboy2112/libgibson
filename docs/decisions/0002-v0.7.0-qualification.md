## Node J: licensing analysis (facts, not legal advice)

The port is a **local, unpublished** prototype: its own git repository with no remote, never
part of this repository. It was inspected on 2026-11-13.

1. **Upstream work.**
   - It derives from **doomgeneric** (https://github.com/ozkl/doomgeneric) at commit
     `e257a09527062bfb986b6e5e0780839b6cbd5b71`. That source is fetched locally and not
     committed in the port.
   - doomgeneric's repository `LICENSE` is the GNU GPL **version 2** text. 177 of its C files
     carry the notice "version 2 of the License, or (at your option) any later version". About 15
     files (doomgeneric's own platform and glue files, among them `doomgeneric.c` and
     `doomgeneric.h`) carry no per-file notice, so the repository's v2 licence governs them. The
     combined work is therefore distributable under **GPL-2.0**.
   - Copyright notices in the C files name id Software (1993–1996), Simon Howard (2005–2014),
     Raven Software (1993–2008) and others.
2. **The port's own files.**
   - Its glue and measurement tools are marked `GPL-2.0-or-later` (SPDX headers). That is
     compatible with distributing the combined work under GPL-2.0. `tools/build.sh` carries no
     licence header; the repository-level `COPYING` (GPL-2.0 text) covers it.
   - Its `NOTICE` lists every component and keeps doomgeneric's notices as cloned.
   - LibGibson's framebuffer adapter is copied into the port unchanged under its own
     `MIT OR Apache-2.0` header. Copying permissive code into a GPL program is compatible in that
     direction and does not change LibGibson's licence.
3. **Separation.**
   - Published, the port would live in its **own repository**, linking LibGibson only as an
     installed SDK via `pkg-config`. LibGibson never vendors or links GPL code.
   - The in-repository clean-room adapter (`bindings/framebuffer_adapter/`, #299) is
     `MIT OR Apache-2.0` and contains no doomgeneric code. Its only references are comments that
     describe a pixel-buffer layout (32-bit XRGB) and a "doomgeneric-style" usage note.
4. **Third-party assets, names and trademarks.** Two points are **not clean as the port stands**:
   - **Rendered game art.** The port's repository commits 22 PNG snapshots of rendered
     **Freedoom 0.13.0** frames (measurement output). Freedoom is BSD-3-Clause. Redistributing
     those images needs Freedoom's copyright notice and licence text, which the port does not
     include (its `wad/` directory, which holds `COPYING.txt`, is not committed). No game data
     file (WAD) is committed.
   - **Name.** "Doom" appears in the port's repository name, README and binary name. "DOOM" is a
     trademark of id Software. Whether that use is acceptable for a public repository is a legal
     judgment that this analysis cannot settle.

**Result.** Points 1–3 are consistent. Point 4 is not clean and unambiguous. Per the owner's
instruction, **v0.7.0 ships without node J** (gate G15 is closed by this decision, not by
delivery).

The port could be reconsidered later if all of the following happen:
- the PNGs are removed, or published with Freedoom's notice;
- `tools/build.sh` gets a header;
- the repository and binary are renamed to avoid the trademark, or the owner obtains and records
  a judgment that the name is acceptable;
- this analysis is redone on the cleaned tree.

Creating a public repository is a separate, explicit owner action.

## Clean-room node J

The replacement is tracked as its own issue ("clean-room node J"). It must be an **original**
program:
- not a port or recreation of any existing game;
- its implementers do **not** read the GPL port or doomgeneric source.

It may use LibGibson's public SDK documentation and the in-repository
`bindings/framebuffer_adapter/` (`MIT OR Apache-2.0`).
